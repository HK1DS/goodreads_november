## Intent filtering definition

Count distinct items present in the train split connected to each intent, before the existing cap of 32. Only intents with positive train-item degree enter the percentage denominator. Sort by degree descending, then original intent ID ascending, and remove floor(active_count * percentage / 100). Remove every incident user and item edge. Preserve intent IDs, embedding rows and shape, and the order of remaining edges; then apply the existing cap and normalization. User-only or held-out-item-only intents are outside the removal denominator. Intent embeddings stay frozen as in IKGR_dyn.

## Requested pause and resume

The user chose saving only when a pause is requested, to release the GPU for games without paying for a save every epoch. From a second terminal in the repository directory:

```powershell
..\venv\Scripts\python.exe scripts/run_todo_5_8.py --pause
..\venv\Scripts\python.exe scripts/run_todo_5_8.py --status
..\venv\Scripts\python.exe scripts/run_todo_5_8.py --resume --phase all
```

Use the same `--config` and `--phase` as the original launch. `--pause` requests a stop; it does not immediately kill the process. Wait for status `paused` and `gpu_released: true` before starting a GPU-heavy game. The child exits after finishing the current epoch and its scheduled validation, updating early stopping, and atomically saving the state. During preparation or final evaluation/export, stopping waits for that stage to finish. Between runs, completed results suffice and no training snapshot is needed.

The snapshot includes current model/optimizer, Python/NumPy/CPU/CUDA random states, train/validation/test loader generators, completed epoch, early-stopping state, best validation metrics, loss history and accumulated active training time. It also embeds the best validation model independently of the latest model: a pause must not change model selection. Thus pause files are larger than ordinary best-only checkpoints. Snapshots are replaced atomically and are removed only after all per-user files and the completed result are committed. Pause duration and data reconstruction are excluded from `train_sec`.

Resume rebuilds the identical dataset/model, rejects a changed code/data/config/seed fingerprint, restores state and continues at the next epoch. It does not rerun the seven-model preflight on every resume. A completed fit (including early stopping) resumes evaluation without another optimizer step. The implementation targets the fixed RecBole 1.2.0 protocol: one process, worker=0, uniform negatives and full precision. The OS lock prevents two launchers from using the same output directory. The parent launcher never retains a CUDA context; preflight runs in a separate child.

This is controlled pause/resume, not automatic crash recovery. Force-killing during an epoch does not save that epoch; an unrequested crash may require restarting the current seed. Do not edit code/config, change hardware, or delete inputs while paused. A changed environment is refused rather than silently mixing experiments. The normal training checkpoint still follows the existing best-validation policy when no pause is requested.
