선택한 방식
- 중지 요청 때만 별도 재개용 상태를 저장한다. 기존 최고 validation 모델 저장 정책은 유지한다.
- 현재 epoch와 예정된 validation/조기 종료 처리가 끝난 뒤 저장하고 프로세스를 종료한다.
- 현재 가중치/옵티마이저, 난수, 데이터 순서, 조기 종료 기록과 별도의 최적 모델을 함께 보존한다.
- 재개하면 동일 상태에서 다음 epoch부터 진행한다. 이미 조기 종료/학습 완료한 상태는 평가부터 진행한다.
- 게임은 상태가 paused 및 gpu_released=true로 표시된 뒤 실행하면 된다.
- 준비/최종 평가/결과 내보내기 중에는 해당 단계가 끝날 때까지 기다릴 수 있다.

중지 완료/진행 상태 확인:

재개:
..env\Scripts\python.exe scripts/run_todo_5_8.py --resume --phase all

phase 5 또는 8만 실행했다면 재개도 동일 phase를 지정한다.
사용자 정의 --config를 사용했다면 중지/상태/재개 모두 동일 파일을 지정한다.
정식 최초 실행은 별도 지시 이후 --run --phase all로 진행한다. 이번 준비에서는 실행하지 않았다.

검증 결과
- 테스트 36개 통과(전체 실행 35개 + 실행기 수명주기 검사 1개).
- 별도 프로세스에서 CPU BPR/IKGR 및 CUDA IKGR의 연속 실행과 중지·재개 실행을 비교.
- 마지막 가중치, 최적 모델, 옵티마이저, 손실 이력, 조기 종료 시점, 예측 점수, 다음 배치와 난수가 정확히 일치.
- 검증 전후 중지, 반복 중지, 조기 종료 직후 중지, 입력 지문 불일치 거부, 동시 실행 잠금 검사 통과.
- 실제 eval_slices 흐름에서 중지 시 미완료 결과를 내보내지 않고, 재개 후 validation/test/인기도 재랭킹 결과 저장 및 완료분 재사용 확인.
- 기존 합성 데이터 TO/TO_GLOBAL 통합 검사, 누수 거부 검사도 통과.
- 전체 실제 데이터 21회 학습은 아직 하지 않았다. 합성 데이터 재현 검증을 전체 학습의 정확도 결과로 사용하지 않는다.

저장 비용
이전 일반 체크포인트 실측에 더해, 최적 모델을 별도 보존하는 새 저장 형식의 직렬화 시간을 측정했다:
- BPR: 약 88MiB, 저장 0.15~0.22초.
- IKGR_dyn_nointent: 약 222MiB, 저장 0.37~0.40초.
- IKGR_dyn: 약 527MiB, 저장 0.79~0.97초.
위 시간은 3회 반복 저장 실측이며, 저장 직전 최적 모델 읽기와 프로세스 준비는 제외한다.
매 epoch 재개 파일을 쓰지 않으므로, 일시중지하지 않으면 이 저장 비용은 발생하지 않는다.
재개 준비 시간은 기존 초기화에 근거해 약 1~3분 예상이며, 실제 데이터의 전체 재개 시간을 측정한 수치는 아니다.
